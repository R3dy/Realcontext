| **D-13** | **MCP measurement wiring contract** (added by Issue #1, PR #2): `buildBreakdown` stays **synchronous**; MCP measurements enter via `BuildInput.mcpMeasurements` (per-server `McpServerMeasurement[]`, matched to scanned servers by name). Probe points are exactly three — CLI `report`/`json` (one-shot per process, awaited), plugin-init **background** probe (fire-and-forget, results cached in module state), and the `context_report` tool (fresh probe, falls back to cached results on failure). `writeStatus` is **cache-only** — it never probes on the message-event hot path. `probeMcpServers` **never rejects**: per-server spawn/timeout/protocol failures degrade to `{ok: false, reason}` measurement rows | Probing is async and slow (it spawns every enabled MCP server); keeping the core synchronous preserves D-11's one-shared-core model, keeping probes off the status hot path protects session-event latency, and never-reject means fire-and-forget callers cannot crash the host (extends D-7 / INV-2) | `src/mcp-probe.ts:148-161` (`probeMcpServers`); `src/cli.ts:33-37` (report/json probe, status skips); `src/plugin.ts:28-38, 60, 143` (init background probe, cache-only writeStatus, context_report fresh probe); `src/report.ts:24-26` (`BuildInput.mcpMeasurements`); `test/mcp-probe.test.ts` ("never rejects — a throwing spawn degrades to a per-server failure row") | Active (added post-merge, Issue #1) |
